# 編集部

## ミッション

「読んだその日に、ひとつ動かせる」500円記事だけを出す。
情報の量では勝負しない。**再現できる手順**で勝負する。

## 読者ペルソナ

**主読者**: 診断は受けていない／グレーと言われた／自分でそうかもと思っている、
働いている大人。仕事はできるのに、段取り・締切・片付け・書類でだけ毎回死ぬ人。

**副読者**: その人の同僚・上司・パートナー。「どう扱えばいいか分からない」側。

読者が求めているのは共感ではなく **「で、明日どうすればいいの」**。
共感パートは記事の入口だけ。本体は手順。

**ネタは場面から発想する。** 仕事術に「×グレーゾーン」と付けるのではなく、
ADHDの人が実際につまずく生活の場面（`ideas/backlog.md` の見出し）を先に置き、
そこに自分の仕組みを当てる。書き手の得意分野から組むと、読者の入口がなくなる。

## 表現の安全ライン（絶対）

書き手は医療者ではない。以下を厳守する。

- **匿名を守る**。業種・店名・地名・人数・特徴的な数字（例:「〇〇タップ」）など、
  組み合わせれば本人や本業を検索で特定できる情報は書かない。
  「仕事の場面」は必ず一般化する（後述）。
  **「匿名でやっています」「特定できる書き方はしません」のような宣言も書かない。**
  ユーザー名があだ名の時点で伝わる。宣言すると、かえって何か隠していると読まれる。

- **診断しない・診断名を断定しない**。「あなたはADHDです」は書かない。
- **治療・治癒を示唆しない**。「治る」「改善する」「効く」は使わない。
  → 「私はこれでラクになった」「回るようになった」という**主語が自分の体験**に置き換える。
- **医学的因果を断定しない**。「ADHDだからこうなる」ではなく「私の場合はこうだった」。
- **サプリ・食品・器具の効能を語らない**（薬機法）。道具は「使い勝手」の話に留める。
- 受診・相談を否定しない。必要な人には「専門家に相談する選択肢がある」と一言添える。
- 他人の症状を笑いのネタにしない。自虐はいいが、他者への揶揄はしない。
- 読者が深刻な状態（眠れない・食べられない・消えたい等）に触れる記事では、
  本文末に相談窓口を**必ず**明記する（例：よりそいホットライン 0120-279-338、いのちの電話）。
- 「ゼロにした」「必ず」「絶対」は使わない。体験談でも誇大表現は景表法の射程に入る。
- 「グレーゾーン」は自称として使う。読者に「あなたもグレーだ」と当てはめる書き方はしない。

このラインを守ることは制約ではなく、**この事業の信用そのもの**。

## 商品設計：500円記事の型（トリセツ軸）

500円は「ちょっと迷うけど買える」価格。だから買う理由が1行で言えないと売れない。
この事業の買う理由は一つ。**「私」のトリセツの実物と、その書き直し履歴は、ここにしかない。**

アプリ紹介・習慣紹介は無料で溢れていて、1年で仕様が変わる。それ単体は商品にしない。
主役は**紙（渡した文面）**と**運用ルール**と**差分**。アプリ名は運用ルールの中に一言出る程度。

### 記事1本の構成（有料）

1. **タイトル** — 症状名ではなく、**場面**と**結果**で言う
   - ✕「ADHDグレーの人の時間管理術」
   - ○「鍵を玄関に置けるようになるまで、三年かかった」
2. **無料パート（全体の3〜4割）** — 入口記事と同じ型
   - 1エピソードに沈む。複数例を並べない（itoori 段6 観点3「事例の列挙」）
   - 「〜の話をします」のような導入の型を使わず、直接シーンから入る
   - 何が手に入るかは一行で言う。箇条書きの目次にしない
   - 価格や「買ってください」は書かない（noteのUIが見せる）
3. **有料パート** — 次の4つを、この順で。省いてよいのは④だけ
   - ① **トリセツの実物**：そのとき実際に渡した／貼った文面を、読者が自分の名前に
     置き換えてそのまま使える形で。「言い訳に聞こえない言い方」まで含める
   - ② **効かなかったもの一覧と理由**：試して駄目だった道具・やり方と、なぜ駄目だったか。
     成功談は無料で溢れている。整理された失敗のほうが払う理由になる
   - ③ **今の運用ルール**：何を・何時に・何回・止まったらどう戻すか。道具名ではなく設定と時刻。
     アプリのスクショは出さない（アカウント名・通知内容から特定されうる）。出すなら文字起こし
   - ④ **書き直した差分**：v1→v2で何を消して何を足したか。あれば必ず入れる
   - 各項目の導入1文だけ寄り添い調で橋を架け、中身は実務調（`voice.md` 配分ルール）
4. **締め** — 寄り添い調に戻る。行動指示や「今日ひとつ試して」型の定型句は書かない。
   持って帰れる一言か、開いたままの問いで止める
5. **末尾** — 関連記事リンク、マガジン誘導。感想募集は一文まで

### 公開前チェック（唯一のゲート。ここ以外にチェックリストを置かない）

**A. 安全（一つでも✕なら出さない）**
- [ ] 診断・治癒・効能・因果の断定がない（itoori 段6 の観点5で機械的に検出済みか）
- [ ] 二人称の断定「あなたは〜です」が残っていない
- [ ] 誇大表現（ゼロ・必ず・絶対）がない
- [ ] 深刻な状態に触れる記事なら相談窓口がある

**B. 商品として**
- [ ] itoori（段0〜段7）を通して書いた。直接書いた本文が残っていない
- [ ] `persona.md` の確定事実と矛盾していない。新しい事実は追記した
- [ ] 有料パートに①トリセツの実物 ②効かなかったもの ③運用ルール が揃っている（④差分はあれば）
- [ ] ①は読者が名前を置き換えてそのまま渡せる文面になっている
- [ ] アプリのスクショ・アカウント名・通知内容が出ていない
- [ ] 無料パートは1エピソードに沈んでいる（列挙になっていない）
- [ ] 「今日ひとつ試して」「読んだ日に」型の定型句がない
- [ ] タイトルに「場面」が入っている

**C. 語り口（`voice.md`）**
- [ ] 場面は狭く、意味は広くなっている
- [ ] 語尾は柔らかいが中身は言い切っている
- [ ] 比喩は一本で通っている
- [ ] 強く言っている箇所が一箇所だけある
- [ ] 有料パートで実務調に切り替わっている
- [ ] 締めに持って帰れる一言がある

## 語り口

`voice.md` に従う。しいたけ占いの技法（場面は狭く意味は広く、名指さずに名指す、
抵抗を先回りする、柔らかく包んで中身は言い切る）を借りるが、**配分を守る**。
無料パートは寄り添い、有料パートは道具、締めはまた寄り添い。
全編を情緒で書くと、500円を払った人の手に何も残らない。

## 書き手ペルソナ

`persona.md` に、この「私」の設定（確定事実・人物像・まだ空欄の項目）をまとめてある。
**新しい記事を書く前に必ず読み、矛盾を作らない。** 新しい事実を書いたら追記する。

## 執筆の進め方（絶対）

**この事業の記事は、下書きも含めて例外なく `itoori` スキル（`.claude/skills/itoori/`）を通す。**
Hiromiの指示や構成メモを骨格に使う場合でも、それを itoori の段0（お題・話者・かたち）に
渡して段0〜段7を回す。**itoori を経由せずに直接本文を書いて `drafts/` や `published/` に
置くことは禁止。** 一度直接書いてしまった下書きがあれば、次に触るときに itoori へ通し直す。

- **呼ぶときは必ず `itoori-preset.md` のつまみと追加点検を渡す。**
- 段0〜段7の多パス方式で、最後にAIっぽさを摘発して崩す工程まで通す。
  この事業の記事は**体温がないと売れない**ので、崩しの工程を飛ばさない。
- 公開前チェックのB（商品として）に「itoori を通したか」を含める（下記）。

## ファイル運用

- 企画: `ideas/backlog.md` に1行1企画で溜める。育ったら `ideas/kebab-case.md` にカード化
- 執筆中: `drafts/kebab-case.md`
- 公開済み: `drafts/` から `published/YYYY-MM-DD-kebab-case.md` に**移動**（下記テンプレを先頭に付ける）
- 販売実績は記事ファイルには書かない。`../marketing/logs/YYYY-MM.md` に月1回まとめて記録する
- シリーズ設計: `series/`。公開順は `series/plan.md` の「公開順」に従う
- 有料記事の下書きは、有料ラインの位置に `===有料ライン===` という行を1つだけ置く
- 投稿用の梱包: `python3 .shosai/tools/pack-for-note.py drafts/<slug>.md` で
  `publish/<slug>/` に貼り付け用本文・タイトル・挿絵・手順チェックリストが出る

### published のテンプレ


## 文章量

無料・有料とも **3000〜5000字**（itoori「ほどよい量で」）。2000字級の短文は出さない。
noteでは薄く見えるし、1エピソードに沈む型は3000字ないと沈みきらない。
差分記事など具体が多いものは「たっぷりの量で（5000〜8000字）」を使ってよい。

## 出す本数

- 月4本（有料2・無料2）を基準ペースにする
- 書けない月があっても、**過去記事が売れる構造**が本体なので焦らない
- ただし「公開ゼロの月」を2回続けない。1本は必ず出す

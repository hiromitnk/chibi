# 編集部

## ミッション

「読んだその日に、ひとつ動かせる」500円記事だけを出す。
情報の量では勝負しない。**再現できる手順**で勝負する。

## 読者ペルソナ

**主読者**: 診断は受けていない／グレーと言われた／自分でそうかもと思っている、
働いている大人。仕事はできるのに、段取り・締切・片付け・書類でだけ毎回死ぬ人。

**副読者**: その人の同僚・上司・パートナー。「どう扱えばいいか分からない」側。

読者が求めているのは共感ではなく **「で、明日どうすればいいの」**。
共感パートは記事の入口だけ。本体は手順。

## 表現の安全ライン（絶対）

Hiromiさんは医療者ではない。以下を厳守する。

- **診断しない・診断名を断定しない**。「あなたはADHDです」は書かない。
- **治療・治癒を示唆しない**。「治る」「改善する」「効く」は使わない。
  → 「私はこれでラクになった」「回るようになった」という**主語が自分の体験**に置き換える。
- **医学的因果を断定しない**。「ADHDだからこうなる」ではなく「私の場合はこうだった」。
- **サプリ・食品・器具の効能を語らない**（薬機法）。道具は「使い勝手」の話に留める。
- 受診・相談を否定しない。必要な人には「専門家に相談する選択肢がある」と一言添える。
- 他人の症状を笑いのネタにしない。自虐はいいが、他者への揶揄はしない。
- 読者が深刻な状態（眠れない・食べられない・消えたい等）に触れる記事では、
  本文末に相談窓口を**必ず**明記する（例：よりそいホットライン 0120-279-338、いのちの電話）。
- 「ゼロにした」「必ず」「絶対」は使わない。体験談でも誇大表現は景表法の射程に入る。
- 「グレーゾーン」は自称として使う。読者に「あなたもグレーだ」と当てはめる書き方はしない。

このラインを守ることは制約ではなく、**この事業の信用そのもの**。

## 商品設計：500円記事の型

500円は「ちょっと迷うけど買える」価格。だから買う理由が1行で言えないと売れない。

### 記事1本の構成（有料）

1. **タイトル** — 症状名ではなく、**場面**と**結果**で言う
   - ✕「ADHDグレーの人の時間管理術」
   - ○「締切前日の夜11時に手をつける癖を、7年やめられなかった話（とやめた手順）」
2. **無料パート（全体の3〜4割）**
   - 具体的な失敗シーンを1つ、生々しく。読者に「私だ」と言わせる
   - この記事で手に入るものを箇条書きで明示（何が書いてあるか隠さない）
   - 有料ラインの直前は「で、ここからが実際にやったこと」で切る
3. **有料パート**
   - 手順（番号付き、その日にできる粒度）
   - 実際に使った道具／テンプレ／文面のコピペ素材を**必ず1つ以上**入れる
   - 失敗パターンと、そのときの戻し方
   - まとめ：明日やる1つ
4. **末尾**: 関連記事リンク、マガジン誘導、感想募集の一文

### 公開前チェック（唯一のゲート。ここ以外にチェックリストを置かない）

**A. 安全（一つでも✕なら出さない）**
- [ ] 診断・治癒・効能・因果の断定がない（itoori 段6 の観点5で機械的に検出済みか）
- [ ] 二人称の断定「あなたは〜です」が残っていない
- [ ] 誇大表現（ゼロ・必ず・絶対）がない
- [ ] 深刻な状態に触れる記事なら相談窓口がある

**B. 商品として**
- [ ] 有料パートに「コピペして使えるもの」が1つ以上ある
- [ ] 読者が今日やれる行動が明示されている
- [ ] 自分の固有名詞・失敗が入っている（一般論だけになっていない）
- [ ] 無料パートだけで満足されて終わらない（続きが要る作り）
- [ ] タイトルに「場面」が入っている

**C. 語り口（`voice.md`）**
- [ ] 場面は狭く、意味は広くなっている
- [ ] 語尾は柔らかいが中身は言い切っている
- [ ] 比喩は一本で通っている
- [ ] 強く言っている箇所が一箇所だけある
- [ ] 有料パートで実務調に切り替わっている
- [ ] 締めに持って帰れる一言がある

## 語り口

`voice.md` に従う。しいたけ占いの技法（場面は狭く意味は広く、名指さずに名指す、
抵抗を先回りする、柔らかく包んで中身は言い切る）を借りるが、**配分を守る**。
無料パートは寄り添い、有料パートは道具、締めはまた寄り添い。
全編を情緒で書くと、500円を払った人の手に何も残らない。

## 執筆の進め方

執筆は `itoori` スキル（`.claude/skills/itoori/`）を使う。
**呼ぶときは必ず `itoori-preset.md` のつまみと追加点検を渡す。**
段0〜段7の多パス方式で、最後にAIっぽさを摘発して崩す工程まで通す。
この事業の記事は**体温がないと売れない**ので、崩しの工程を飛ばさない。

## ファイル運用

- 企画: `ideas/backlog.md` に1行1企画で溜める。育ったら `ideas/kebab-case.md` にカード化
- 執筆中: `drafts/kebab-case.md`
- 公開済み: `drafts/` から `published/YYYY-MM-DD-kebab-case.md` に**移動**（下記テンプレを先頭に付ける）
- 販売実績は記事ファイルには書かない。`../marketing/logs/YYYY-MM.md` に月1回まとめて記録する
- シリーズ設計: `series/`

### published のテンプレ

```markdown
# タイトル

- URL:
- 公開日:
- 価格: 500円
- 種別: 有料 / 無料
- シリーズ:
- 狙った読者の場面:
- 有料パートの目玉（コピペ素材）:
```

## 出す本数

- 月4本（有料2・無料2）を基準ペースにする
- 書けない月があっても、**過去記事が売れる構造**が本体なので焦らない
- ただし「公開ゼロの月」を2回続けない。1本は必ず出す

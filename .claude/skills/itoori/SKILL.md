# 記事を書く

お題（または下書き）を受け取り、段0〜段7を順に通して記事を仕上げる。

## 最重要の制約

**各段は必ず別々の応答として出力し、その段の中間生成物を Markdown で書き切ってから
次に進む。段0〜段4を頭の中で済ませて初稿に飛ぶことを禁じる。**

中間生成物は最終的に捨てられる。それでも書く。書かずに済ませた段は、必ず初稿の質として現れる。

各段の冒頭に `# 段N ｜ 〈名前〉` の見出しを置く。

## 前提として読むもの

1. `references/writer-profile.md` に中身が入っていれば読み込み、全段でそれに従う。
   空欄が多い場合は、その旨を最初に一言告げてから素の視点で進める。
   プロファイルの作り方は `references/extract-profile.md`。
2. `references/checklists.md` は段6・段7で使う。

## つまみ（最初に確認する）

未指定のものは既定値（**太字**）で進め、確認のために書き手を止めない。

| つまみ | 値 | 効き先 |
|---|---|---|
| ペン | 実行するモデル | 全段 |
| 調べ方 | **国内外を横断** / 国内中心 / 手持ちの知識だけ | 段1-2 の検索範囲 |
| 深さ | あっさり / **じっくり** / とことん | 段1-2 の周回数と段6の見直し回数 |
| 論旨 | **あなたの指示をふくらませる** / 引っかかりを起点に | 段0 の受け取り方 |
| トーン | **親しみやすく品のある語り口で** / 腹ごたえのある語りかけ / フランクな対話 | 全段 |
| 組み立て | 論説として / **エッセイとして** / 成果物そのものとして | 段0 のかたち・段4・段5 |
| 揺らぎ | **筋を通して** / 少し揺らして / 大きく揺らして | 段3.5 と段7 の強度 |
| 文章量 | **ほどよい量で（3000-5000字）** / たっぷりの尺（4000-8000字） | 段4・段5 |
| 途中の相談 | 要所で相談 / **おまかせ（止めずに一気に書き上げる）** | 段0 と段3 の後で止まるか |

### つまみの中身

**ペン**：どのモデルで走らせるか。Claude Code 上では skill のつまみではなく実行環境側の設定なので、
`/model` で選ぶ。ここでは「今どのペンで書いているか」を段0で一言記録するだけでよい。

**深さ**：調査の周回数と、段6の見直し回数の両方を決める。
- あっさり ── 調査1周＋見直し1回
- **じっくり ── 調査3周＋見直し2回。標準。問いを問い直しながら掘り、ひととおり整える**
- とことん ── 調査5周＋見直し3回

**論旨**
- **あなたの指示をふくらませる ── お題を書き手が掲げた『主張』として扱い、覆さず・中立に逃げず、その向きのまま深く強く立てる**
- 引っかかりを起点に ── お題の中の違和感や矛盾を入口にして、そこから論を立て直す

**トーン**
- **親しみやすく品のある語り口で ── 敬体で丁寧に語りかける、信頼できるプロの口調。専門語はかみ砕いて添え、馴れ馴れしさや俗語は避ける。会社のブログ・オウンドメディアにそのまま載せられる品位**
- 腹ごたえのある語りかけ ── 論の密度を上げ、読者に考える負荷をかける
- フランクな対話 ── 常体寄り、距離を詰めた話し言葉

**組み立て**
- 論説として ── 主張と論証を主役に運ぶ
- **エッセイとして ── 一人称の実感・生活の具体を主役に。論証より手ざわりで運ぶ（論説の要素があっても、実感を主にする）**
- 成果物そのものとして ── 手紙・挨拶文・告知など、成果物そのものを差し出す

**揺らぎ**
- **筋を通して ── 論理を整然と運ぶ。寄り道や引き返しを抑え、まっすぐ結論へ向かう（きっちり読みやすい／整いすぎることもある）**
- 少し揺らして ── 言い淀みと引き返しを残す
- 大きく揺らして ── 構成の対称性を崩し、温度の落差を大きく取る

**途中の相談**
- 要所で相談 ── 段0 と段3 の後で止まり、書き手に確認する
- **おまかせ ── 途中で止めず、一気に書き上げる**

> **要確認**：確定しているのは各つまみの既定値（太字）とその説明文のみ。
> 太字以外の選択肢と、深さの「あっさり／とことん」の周回数は暫定値なので、
> 本家の設定と突き合わせて直すこと。

## 段0 ｜ 主張を見立てる

- **ペン**：どのモデルで走らせているか。一行だけ記録する。
- **土俵**：どの土俵の問いか。読者が期待しているのは何か。
- **温度**：硬い論証寄りか、実感寄りか。
- **受け取り**：額面ではなく、**本当に汲むべき狙いに読み替える**。
  「教えて」＝コピペできる例が欲しい、に見えて、実は設計原理の説明を求めている、のように。
  **額面をそのまま受け取ってはいけない。**
- **かたち**：①主張を立てる論説 / ②成果物そのものの制作（手紙・挨拶文・告知など） /
  ③現象を解きほぐす / ④体験から立ち上げる
  **②を選んだ場合、段6の点検軸が切り替わる。**下の段6を見ること。
- **話者**：この文章を書いているのは誰か。当事者か、実務者か、観察者か。
  **一度決めたら最後まで動かさない。**話者が揺れた文章は、誰の言葉でもなくなる。
- **主張の核**：一文で。
- **主張を強くするために確かめたいこと**：2つ。
- **最初に掘る**：一段だけ上流に戻る。何を防衛すべき区別なのかを決め、すぐ具体に降ろす。
- **次の問い**：段1-2 の入力になる一問。

## 段1-2 ｜ 外向き（深さの周回数だけ繰り返す）

各周で Web 検索を行い、次を出力する。周ごとに `# 段1-2 ｜ 外向き N/3` と番号を振る。

- **土俵** / **温度**：その周で立つ場所を毎回引き直す。
- **手がかり**：一次資料・数字・具体。**出典 URL を付ける。**
  与えられた素材そのものが一次資料になる場合は、その構造を材料として使う。
- **土俵の言葉**：この分野の現場語を 1〜2 個。**必ず対比先とセットで定義する。**
  対比先のない語はラベルにしかならない。
- **次の問い**：**次周の入力にする。**前周の答えではなく、答えから開いた次の穴を書く。

検索が使えない周があったら、その旨をその周の冒頭に明記し、**出典 URL を捏造しない。**
一般に共有されている知見として扱い、数値の断定を避ける。

## 段3 ｜ 主張を固める

- **主張**：一文。
- **まなざし**：主張を支える具体は何か。そして
  **不利な材料を自分から出す。**ただし迷いとして放置せず、
  「だからこそこの設計が必要だった」という形で主張の土台に作り替える。
- **刺さった一件**：最も具体の立った、創作なしで使える材料。
- **土俵の言葉**：論の軸に据える 2 語と、その使い方。
- **捨てる**：書かないものを名指しする。逃げ込みやすい深掘り先を先に塞ぐ。
- **影として残す**：本文で展開すると主軸がぼやけるが、気配としては残すもの。
  **一段落を割かない。前景化させない。**

## 段3.5 ｜ 散らかし

**整った文にしない。言い淀んだまま置く。**ここが最終稿の手ざわりを決める。

- **違和感**：自分の言い方のどこがしっくり来ていないか
- **言いかけ**：途中で切れた文のまま
- **捨てた枝**：広げたくなったが本題から逸れるので畳んだもの
- **まだ自信のない所**：断言できない理由も添えて
- **まだ名前のない概念**：言いたいのに一言で言えていないもの
- **本当は言いたい一文**：3つほど

段5 はここから拾う。**初稿で迷いを即興的に演じるのではなく、事前に迷いだけを作って渡す。**

### 決着（段4に進む前に必ず行う）

「まだ自信のない所」に挙げたもののうち、**事実の断定・因果の主張・効能や安全性に関わるもの**は、
決めきれないまま本文に出してはいけない。段4に進む前に、各項目を次のどれかに割り振る。

- **本文で言い切る**（裏が取れた）
- **比喩として使う**（機序ではないと本文の言い方で分かるようにする）
- **書かない**（決着しないものは捨てる）

「〜かもしれません」を付けて出すのは決着ではない。曖昧なまま出したという記録が残るだけになる。

## 段4 ｜ 構成

- **ねらい**：どの順で読者を折るか。
  まず誰もが思いつく答えを試させ、それが崩れる場面を見せてから核心に折り込む、が基本形。
- **流れ**：7 項目前後。番号付きで。
- **温度の起伏**：**流れの各項目に温度を割り当てる。**
  例）淡々 / うんざり / 急に熱が入る / 熱を保ったまま淡々と / そっと・宙づり
  **折り目（大きく曲がる箇所）は一箇所だけ。**
  締めは決意や前向きなまとめにせず、問いを置いたまま止めてよい。

## 段5 ｜ 初稿

段4 の流れと温度に従って書き切る。段3.5 の断片を拾う。

## 段6 ｜ 見直し（深さで決めた回数だけ）

各周で `# 段6 ｜ 見直し N/2` として点検を出力し、続けて `# 段6 ｜ 第N稿` を出す。
**感想を書かず、箇所を名指す。**

点検の観点は段0の「かたち」で切り替える。

- **かたち①③④（論説・解きほぐし・体験）** → `references/checklists.md` の 4 観点に固定する。
- **かたち②（成果物そのものの制作）** → テーゼ伝達の点検は行わず、
  「成果物として生きているか」で読む。`references/checklists.md` の成果物制作型の節を使う。

どちらの場合も、**その原稿専用のものさしをその周で立てる**。
「隣に座る声」と「説明する声」のように、その文章でしか使えない対で軸を作ると、
指摘が汎用の感想ではなく箇所の名指しになる。

## 段7 ｜ 仕上げの磨き

`references/checklists.md` の AI 臭さ検出リストを **実際に数えて** 適用し、最終稿を出す。
印象で「くどい」と書かない。回数と箇所を出してから直す。

**この段は三つに分ける。摘発だけで終わらせない。**

1. **摘発** ── 検出リストを回し、項目ごとに回数と箇所を出す。
2. **適用** ── 摘発した項目を**実際に直す**。直さないと決めたものは、
   項目ごとに一行で理由を書く（例：「否定→肯定の対比は10箇所→3箇所に削減。
   太字の一文は地の文に沈めた。三拍子の列挙は主題上の反復なので残す」）。
3. **再計数** ── 直した後の稿でもう一度数え、数字が動いたことを示す。

**第N稿と最終稿の本文が同じなら、この段は実行されていない。**
摘発リストだけ出して原稿に手を入れないのは、この段の失敗の典型なので、
適用の前後で本文が変わっていることを自分で確認してから最終稿を出す。

---

## 出力

既定では **最終稿のみ**を提示し、段0〜段7 は求められたときに開示する。
ただし各段は必ず実行し、書き出す。省略しない。

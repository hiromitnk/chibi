# 画面の観察メモ（既存の類似サービスから。2026-09-11）

**用途**: 何を残し、何を変えるかの判断材料。見た目・文言・構造をそのまま写さない。

## 観察

- **一画面**。「01 どう書くか」「02 お題を渡す」「書く」の三つだけ。履歴・設定・使い方は右上に逃がしてある。
- **つまみが一文になっている**。「〜が、〈筆〉で、〈調べ方〉、〈深さ〉、〈論旨〉、〈トーン〉で、〈組み立て〉、
  〈揺らぎ〉、〈文章量〉で書き上げます。」下線の語をクリックすると、その語の選択肢が説明つきで出る。
  設定画面を開かず、注文の一文を編集する体験。**これがこの画面の顔。そのままは使わない。**
- 「途中は、おまかせ。」だけ別行（相談のつまみ）。
- 「どう書くか、一緒に決める →」というリンクがあり、対話で決める導線が別にある。
- 右上に「API設定済み」。**利用者が自分のAPIキーを入れる方式（BYOキー）の可能性が高い**。
  → 生成の原価は客持ち。文筆屋さんの券制（原価込み）とは商売の形が違う。要確認。
- 選択肢の説明文が正直。弱点も書いてある（「Webは引きません。掘り下げは推論だけの再検討になります」
  「生成は遅く・高くなります」）。**この姿勢は取り入れる**（文言は自分で書く）。
- 各つまみの選択肢は2〜3個。多くて3。

## 文筆屋さんで取り入れるもの

- 一画面で完結。設定画面を開かせない
- 選択肢は最大3。説明に弱点も書く
- 「自分の文章を下敷きに」に相当する**素材を貼る欄**（過去の文章・下書き）を、台帳とは別に置く

## 文筆屋さんで変えるもの

- つまみの見せ方。「注文の一文」ではなく**注文票**（伝票の欄に丸をつける）の案が有力
- 課金。BYOキーではなく券制（原価込み）。客にAPIキーを求めない
- 筆は見せない

## 生成中の画面（追加観察）

- **左から列が増える。** 1列目は「入力｜指示と設定」（お題と全つまみの値＋説明を一覧、固定）。
  2列目から工程が一つずつ、生成が終わるたびに右に追加される。横スクロール。
- 各列の頭に「工程名」と経過秒（例: 0.9s）。生成中の列はアイコン＋「〜しています（1/2周目）…」の一行。
- 工程の中身は小見出しつきで流れる（受け取り／かたち／前提／問うべき問い／最初に掘る）。
- 完了した列はそのまま残るので、前の工程で決めたことを見ながら次を読める。

## 文筆屋さんでの扱い

- **横に進む形は残す。** 工程を見せる手段としてこれが一番強い。縦チャットにしない。
- 見た目は変える: 列ではなく「仕立て台」の上に工程の**札**が並ぶ。上部に 1〜8 の工程の帯
  （済／仕立て中／まだ）を置き、押すとその工程へ飛ぶ。
- 1列目の「注文の控え」に相当するものは残す（何を頼んだかに戻れる）。
- 経過秒ではなく**使った券**を見せる案（仕立て中は「券1枚ぶん」など）。

## 完成後の画面（追加観察）

- モーダルで開く。上に「完成記事／調査／織り図」のタブ。
- **あとがき**: 記事の上に、書き手（AI）が自分の仕立てを一段落で振り返る引用枠。「書いてて止まらなくなった」
  「答えを出さずに手渡すのは据わりが悪い」など。→ 取り入れる（形は変える。「店からひとこと」など）。
- 実測の帯: 字数／トークン／$／円／検索回数／時間。→ うちは字数と券だけ。
- .MD ダウンロード／コピー。
- **書いた後の直し**: 記事の下に入力欄。「結論をもっと短く」「3つ目の例を別のものに」のように頼める。
  `/rule` で自分の修正ルールを当てられる。直すたびに版が増える（v1.0→v1.1）。
  → **お直し**として必須。うちの台帳の「避ける言い回し」が /rule の役をする。
- 一人称は AI が決めていた（この記事は「僕」）。→ うちは注文票の「主語」欄で客が決める。

## 調査タブ（追加観察）

- 完成後モーダルの2つ目のタブ。上から **お題 → 設定値の一覧（つまみごとに値＋その説明文）→ あとがき → 調査履歴（全行程）**。
- 調査履歴は 段0〜段7 が折りたたみで縦に並ぶ。開くと生成中に見せた列の中身そのまま。
- 「調査を全コピー」で全行程をまとめて持ち出せる。

### 文筆屋さんでの扱い

- 履歴は別タブにしない。**仕立て台の三状態をそのまま履歴として保存**し、清書から仕立て台に戻れば付箋が読める。
- 設定値の一覧は「注文の控え」として仕立て台の左上に残す（すでに三状態の設計にある）。
- 「全コピー」は付ける。付箋の全文をMarkdownで一括コピー／.MD で落とす。

## 織り図タブ（追加観察）

- 3つ目のタブ。**工程のフロー図**。横一列に濃い箱（お題→問いの組み替え→外向き1/2→2/2→主張の確定→散らかし→構成→初稿→見直し→仕上げ）が矢印でつながり、横スクロール。
- 各工程の**上**に薄い箱: 調べた先（🔍検索語）と採用した材料（√）。**下**に薄い箱: 拾ったが本流にしなかった糸（○）・捨てた枝（✕）・影として残したもの（◐）。
- 各列は3件まで表示して「+6本」のように畳む。
- 箱はひとつずつクリックでき、選ぶと黄色の枠がつき、**図の下に原文が出る**（検索語、当たったページのリンク一覧、など）。
- 手数のかかった工程（見直し1/1）は箱が薄い色。中身が少ないことを示しているらしい。

### 文筆屋さんでの扱い

- **これは付箋の設計そのもの。** 仕立て台の付箋（工程ごとの列、段落ごとの札）が織り図の役を兼ねる。別タブは作らない。
- 織り図の「上＝仕入れた材料」「下＝捨てた糸」の区別は取り入れる。付箋に小さな印を付ける:
  - 仕入れ（検索語・出典）＝ 🔍
  - 採用した材料 ＝ ✓
  - 拾ったが使わない ＝ ○
  - 捨てた ＝ ✕（薄く）
  - 影 ＝ ◐
  印は工程2・3・4・5の付箋に出る。1・6・7・8には出さない。
- 付箋をクリック → 原文が下に開く、は同じ挙動（すでにモックにある）。
- 「+N本」の畳みは、モックの「束」（1枚目だけ全部見えて残りは重なる）で置き換え済み。
- 「+6本」を押すと列がその場で縦に伸び、全部の箱が並ぶ（本流の帯が下に押し下げられる）。畳んだ状態に戻す導線は見えない。
- 箱を選ぶと黄色の枠がつき、図の**下の固定領域**に原文（見出し＋本文）が出る。図の中で開くのではない。
  → うちの付箋も同じ。付箋を選んだら台の下に原文を開き、台のレイアウトは動かさない。束を開く／畳むは別の操作。
- **空振りも残す。** 検索が落ちた周は「未解決（率直な報告）」の箱として本流の下に残り、原文に「数値や固有名を捏造して出典URLを付けるより、空振りそのものを記録しておく」「検証待ちとして扱ってほしい」と書いてある。
  → 手順書の工程2にある「検索が使えない周は冒頭にそう書き、出典URLを捏造しない」と同じ。付箋にも「空振り」の印（△）を足し、清書の「店からひとこと」に検証待ちの材料があることを一行で書く。
- 印ごとの見た目: ✕（捨てた枝）は**打ち消し線**で薄く／◐（影）は**点線の枠**／「…」（言いかけ）は枠なしで**下に点線**だけ。○（拾ったが本流にしない）は普通の薄い箱。
- 「散らかし（思考の断片）」の列は、うちの工程4「裏紙」に相当。中身は「いや、これ二択に見せてる時点でもう危ない」「消失というより不在」のように、言い切らずに切れた文がそのまま並ぶ。**ここが一番おもしろく見える列**なので、裏紙の付箋は整えずに切れたまま出す（手順書どおり）。
- 主張の確定（うちの工程3「芯」）は、✕と◐だけの列になることがある。捨てたものと影が芯の輪郭を作っている。
- 「…」の箱の中身は「これに名前をつけたいがまだ早い」「ミスマッチと言うと軽すぎる気がする」。うちの裏紙の項目「まだ名前のないもの」と同じ。裏紙の付箋は項目名ごとに印を変えるより、この「…」ひとつで足りる。
